# Keep each PR to at most 300 changed lines of production code

## Context
The Hand-Folded Fantasy PRs took hours from push to merge: each deep review and its fixes ran 30 to 90 minutes, and most needed two rounds. Counted with the new check (added plus deleted production lines), the merged PRs were #337 659, #340 714, #339 421, #341 545, #343 325; the two that merged fastest were #342 160 and #338 176.

## Decision
- A PR changes at most 300 production lines and should stay under 200 (CLAUDE.md, Code style). Tests, docs, goldens, fixtures, assets, lockfiles and generated `.import`/`.uid` files do not count.
- `PR checks` runs `scripts/check-pr-size.mjs`: it fails above 300 and warns above 200. The owner's `size-exception` label lets a larger PR through with a warning.
- Larger work is split before it is written: stacked PRs, one ticket each, each with tests and a working build.

## Alternatives considered
- A soft guideline with no check: the epic showed agents drift past any size nobody counts.
- Counting test lines too: tests are cheap to review and the rules ask for more of them, not fewer.

## Consequences
- More, smaller PRs and more stacking; each review fits in one pass.
- PRs in flight when this landed (#344, #345, #346) finish under the `size-exception` label.
