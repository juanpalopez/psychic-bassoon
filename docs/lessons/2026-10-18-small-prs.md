# Keep each PR to at most 300 changed lines of production code

## Context
The Hand-Folded Fantasy PRs took hours from push to merge: each deep review and its fixes ran 30 to 90 minutes, and most needed two rounds. Counted with the new check (added plus deleted production lines), the merged PRs were #337 850 (its moves count as a delete plus an add), #340 714, #339 421, #341 545, #343 325; the two that merged fastest were #342 160 and #338 176.

## Decision
- A PR changes at most 300 production lines and should stay under 200 (CLAUDE.md, Code style). Tests, docs, goldens, fixtures, assets, lockfiles and generated `.import`/`.uid` files do not count.
- `PR checks` runs the base branch's `scripts/check-pr-size.mjs` (`git diff --numstat -z --text --no-renames`): it fails above 300 and warns above 200. The owner's `size-exception` label lets a larger PR through with a warning; agents never touch labels. Making `PR size` a required check in the `main` ruleset is the owner's step.
- Larger work is split before it is written into a `gh stack` of PRs, each under the limit with tests and a working build, reviewed as one stack.
- It applies from the next tasks: #344, #345 and #346, open when it landed, finish as they are with the `size-exception` label (owner, 2026-10-18).

## Alternatives considered
- A soft guideline with no check: the epic showed agents drift past any size nobody counts.
- Counting test lines too: tests are cheap to review and the rules ask for more of them, not fewer.

## Consequences
- More, smaller PRs and more stacking; each review fits in one pass.
